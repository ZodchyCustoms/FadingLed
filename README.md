

Эксперимент.
  Задумка в том чтобы в бесконечном цикле запускать движок engineMain(), а
    в обработчике прерывания по совпадению таймера  движок engineFade().
  engineMain() - в нем постоянно проверять в _update() не запрошено ли
    новое состояние _netState и если да то в следующем периоде цикла
    в _go() выполнить соответствующее действие и сразу перейти в ожидание нового.
  engineFade() - здесь выбирать соответствующее действие для обработки плавного
    изменения яркости в зависимости от текущего(?) состояния _fadeDirection.
    Самое опасное место потому что внутри прерывания...
  Плавным измением яркости занимается таймер (пока что это таймер2).
    Для этого реализуется структура ProgrammPwmChannel которая имеет методы:
      init(uint8_t, uint8_t, uint8_t) - устанавливает переменные:
        top - вершина счета програмного таймера.
        duty - коэффициент заполнения.
        pin - номер пина.
        tick() - эмулирует счет таймера и переключает пин в соответствии с
          заданной скважностью - duty и обнуляет счетчик тиков.
      incrementDuty() - инкрементирует скважность и возвращает true если ОК
        или false если заполнение дошло до заданного константой максимума.
      decrementDuty() - то же только декремент и false когда дошло до 0.
